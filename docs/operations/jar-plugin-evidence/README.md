The pin keeps the same 24 active JAR executions; the owner-resolution report now also lists the managed plugin for the two POM projects. It removes AirCompressor 0.27 from the resolved plugin inventory without changing application dependencies or the other 16 plugin owners.

The retained local capture compares all 26 effective models, 17 plugin owners and the complete dependency graph against accepted main run 1862. The 237 runtime components, 345 runtime edges, six imported BOMs, lockfile, Actions and toolchain inputs remain identical. The full 467-target OSV diagnostic reports 11 to 10 findings: one AirCompressor finding removed, no additions or changes, and ten identical retained records. Plexus Utils 4.0.2 remains in other owners. See [the diagnostic evidence](osv-diagnostic/README.md) and [the exact graph transition](../jar-plugin-transition.json).

The paired offline fixture exercises both JAR versions with the accepted Boot 4.0.8 plugin. Its 21 processes cover 28 JAR goals, two Boot repackages, executable output, default exclusions, empty archives, incremental rebuilds, attachments, expected duplicate-main rejection, multi-release metadata and ZIP payload/CRC checks above the 10 MB offloading threshold. Definition hashes and actual class origins are checked separately from symbolic linkage. ZIP/JAR coverage does not establish Snappy, XZ or Zstd codec execution. Hosted CI runs the same paired fixture and retains both complete receipts after validating them.

These captures and diagnostics are local precommit evidence, not exact-head CI or production release approval. Fresh CI must independently produce complete scanner coverage and acceptance artifacts. Remaining findings and the production release block are preserved.
